Not by the AI's confidence. The class-code rule holds even with AI confidence forced to "high". No regressions.

What testing caught

  • A live run crashed on unexpected AI output (true/false values instead of text).
  • A cross-check silently passed when the column it compares against was missing.
  • Cached AI responses would have made repeat runs look perfectly consistent.
  • Class code "0005" was caught only because the AI happened to be cautious.

What we fixed

  • Every AI output is validated first; a bad column goes to Review instead of breaking the run.
  • A check that can't run now fails safe instead of passing.
  • Caching is off, so repeat runs are real, independent calls.
  • An approved class-code list plus business-type fit, independent of the AI.

How we checked

  • Answer key frozen with checksums before any run.
  • 3 independent live runs, plus a replay with all AI confidence forced to "high".
  • 14 broken-output and 5 messy-value tests; full regression after every fix.

Limits

  • One synthetic blind file, written by the same AI that wrote the key.
  • Small sample class-code list; spreadsheets only (no PDFs).
  • Decisions aren't saved; the client follow-up draft isn't built.
Next step: 10–20 real client files with analyst-approved mappings as answer keys, 3 runs each. Measure wrong auto-applies (target 0), review rate, and time to an approved dataset.
